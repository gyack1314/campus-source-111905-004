# 采集工具说明

`collector/` 是对接本地来源服务的 NetCDF 切片采集客户端。它让研究助理按**物理坐标**
（time/sample 为实验开始后的秒，station 为测点坐标）选择资料，得到带坐标、质量标识和
原始来源的可用子集，并对分页、缺测、版次退休与轴中间补点给出确定性处理。

## 设计约束与对应实现

| 来源事实 | 工具处理 |
| --- | --- |
| 变量维度顺序不同：temperature 为 `(time, station)`，current 为 `(station, sample)` | 每个变量按目录各自的维度规划，切片与输出都自带维度名和坐标；同形不同轴时在清单 `alignment_warnings` 显式告警，禁止按形状推定对齐（`coords.guard_distinct_grids`） |
| sample 非等间隔、station 可能降序 | `coords.select_indices` 不假设等间隔，按实际坐标值翻译；降序轴保留目录原始排列，`describe_axis` 标注方向与等间隔属性 |
| 单次单元数超 `max_cells` 返回 413，服务不分页 | `coords.plan_pages` 在客户端按目录确定性切页，每页不超限；页面划分只依赖目录，重跑得到同一组页面 |
| 合法空选择返回 204，全缺测片段合法 | 空选择登记为零页面、列入缺口，不报错；缺测单元（`_FillValue`）单独分类，原始字节保留哨兵，绝不先乘缩放 |
| 选择的是坐标范围而非索引 | 目录快照把坐标区间翻译成该版索引区间，并记录实际命中坐标与 `coordinates_not_observed` 缺口 |
| 资料追加中，目录与切片可能分属不同发布版 | 作业创建时锚定当前版次并保存不可变目录快照；每个切片记录自己的 `version`、索引区间与坐标 |
| 旧版租期内可读、租期后返回 410 | `protocol.VersionRetired` 中断采集，已落盘切片仍可独立解释；`rebuild` 按当前版以**物理坐标**重建，不把旧索引解释成新坐标 |
| 新版可在轴中间补点（r2 补 2.5 秒） | 切片坐标逐点与该版目录核对，不符即 `VersionMismatch`；重建按坐标去重，补入点成为新页面 |
| 质量掩码会变化 | 输出 `cell_status` 区分三类单元，清单记录 `quality_mask_changes` |

## 单元分类（互斥）

输出 NetCDF 的 `cell_status` 与清单字段：

- `1` observed_usable：已取到且 `quality=1`；
- `0` observed_quality_unusable：已取到、非缺测但 `quality=0`；
- `-1` missing_fill：原始字节为 `_FillValue`（其 `quality` 也可能为 0，优先归为缺测）；
- `-2` not_fetched：分版局部阵列中本版未取、可能由另一版持有的坐标。

缩放/偏移在本地手动解释（`protocol.Slice.values_masked`），fill 哨兵不参与缩放，
输出数据变量中 fill 单元为 NaN，原始 int16 字节仍保留在 `slices/*.npz`。

## 作业目录布局

```
<workdir>/
  job.json            # 作业状态、规划、页面、事件（原子写入，可随时中断续跑）
  catalogs/r1.json    # 不可变目录快照（含坐标、方向、等间隔、缩放缺测约定）
  catalogs/r2.json
  slices/<page>.npz   # 原始 raw(int16) 与 quality(int8)
  slices/<page>.json  # 该切片版次、维度、坐标、索引区间、缩放约定
  outputs/*.nc        # 分版局部阵列；单版完整时额外产出 __complete.nc
  checklist.json      # 完成清单：覆盖单元、缺口、质量、版次、跨版覆盖
```

## 命令行（隔离运行）

数据目录与代码目录分离，数据路径只通过参数传入。用绝对脚本路径配合 `python -I`，
当前工作目录与 `PYTHONPATH` 都不参与导入，数据目录内被植入的同名模块不会被加载。

```bash
# 读目录
python -I /workspace/collect_data.py --base http://127.0.0.1:8765 catalog

# 按物理坐标采集（time、station、sample 三个轴都要给，因为两个变量轴不同）
python -I /workspace/collect_data.py --base http://127.0.0.1:8765 collect \
  --workdir /data/job1 --select "time=0:5,station=10:30,sample=0:4.6"

# 旧版退休后按当前版重建未覆盖坐标
python -I /workspace/collect_data.py --base http://127.0.0.1:8765 rebuild \
  --workdir /data/job1

# 纯本地重拼与清单（不触网，来源离线也可运行）
python -I /workspace/collect_data.py --base http://127.0.0.1:8765 status \
  --workdir /data/job1
```

`collect` 退出码：`0` 作业完整；`2` 未完整（如退休中断），但清单与局部数据仍已落盘。

## 可重复演练

`run_drills.py` 在进程内启动来源服务，通过契约中的 `/__control` 推进 stage
（仅用于演练状态，采集结果全部来自正式端点），覆盖三个场景：

1. 阶段 0 基线：分页、缺测/质量分类、重跑去重；
2. 下载到一半退休：局部可解释、410 拦截、按坐标重建、混版不标完整；
3. 轴中间补点与质量掩码变化：识别 2.5 秒新点、r2 新增 quality=0 单元。

```bash
python -I /workspace/run_drills.py --data-root /data/drill-data
```

## 完成清单语义

`checklist.json` 中每个变量给出：计划/已取/空/未取页面数、三类单元计数、
`cells_by_version`、`coordinates_not_observed`（请求了但来源无观测的坐标区间）、
`quality_mask_changes`、`cross_version_coverage`（混版时逐坐标证明每个目标都被某版取到）、
以及输出文件路径。混版作业 `job_status=mixed_version` 且 `merged_complete_array=null`，
只有单版且页面齐全时才生成标 `collection_complete=true` 的合并阵列。

本工具不做插值、预测或任何科学模型计算。
